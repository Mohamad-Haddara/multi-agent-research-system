Agentic AI Project File Structure

src/ --> Application package

agents/ --> Agent roles and responsibilities - graph, nodes, tools, prompts

orchestration/ --> Control flow and durable state


api/ --> Application entry points - routes, dependencies, middleware
main.py --> Request endpoints and health checks


/core --> config, logging, errors


ui/ # Streamlit



Run from the project root as a module:
uv run python -m src.api.main

1. Scope - What does it do, and what goes in, what comes out
2. Project setup
    - Create the folder layout
    - Manage dependencies with uv: pyproject.toml + lock file
    - Put .env in gitignore; commit a .env.example with key: no values
    - core/config.py with pydantic-settings: typed settings that fail at at startup if a key missing
    - core/logging.py: KSON logs, with request_id on every line
    - docker-compose.yml: for infrastructure only: Postgres, Qdrant, Redis

3. Define Contracts
Define every data shape before logic that uses it. Endpoints, nodes and tools are
then built against fixed contracts.

        - API schemas: ChatRequest, ChatResponse, StreamChunk, ErrorResponse
        - IDs: request_id generated by the server; thread_id optional in the request;
        user and tenant taken from auth, never from body
        - Agent state: What flows between nodes (messages, intermediate results, step count, errors)
        - LLM output schemas: Pydantic models passed to with_structured_output, one
        per call that must return structure
        - Tool input and output
        - Keep agent state and output schemas separate: state is the graph memory, 
        an output schema shapes one LLM call

5. API Layer
main.py only wires things together. The agent logic stays in agents/ and the API
just exposes it.

    - main.py: an app factory + a lifespan thate creates the LLM, database and vector store clients once
    - Endpoints: POST /v1/chat, POST /v1/chat/stream (SSE), GET /health, GET /ready
    - Middleware: request_id, CORS, timing, global exception handlers that return ErrorResponse
    - Auth (API key or JWT) and rate limiting
    - Async I/O throughout, a request timeout, and long jobs moved to a background worker or queue.
    - Try every endpoint in /docs (Swagger) before building any UI
